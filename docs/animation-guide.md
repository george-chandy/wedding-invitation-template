# Animation Guide

## Library decisions
| Library | Decision | Reason |
|---|---|---|
| **Motion** (`motion` 14.6) | Used | `whileInView` reveals, variants/stagger for the hero, `AnimatePresence` for the nav/menu, `pathLength` line-drawing, `useReducedMotion`. Loaded through `LazyMotion` + `domAnimation` with `strict`, so only the small `m` component is bundled. |
| Motion **mini** `animate` | Used for the envelope | Plain WAAPI: transforms run on the compositor thread and no sequence engine is shipped. |
| **GSAP** | Not used | The envelope is ~8 tracks with delays; WAAPI delays + one multi-keyframe animation express it exactly. Adding GSAP would duplicate responsibilities and add size. Revisit if you need scrubbed/scroll-linked timelines. |
| **Lenis** | Not used | Smooth scroll here means anchors and back-to-top only. Native `scroll-behavior: smooth` (only under `prefers-reduced-motion: no-preference`) + `scroll-padding-top` keeps native history, focus and keyboard behaviour and avoids hijacking scroll. |

Measured cost (production build, gzip): Motion chunk **35.3 kB**, React **65.7 kB**, app code **~16 kB**.

## One owner per property
| Element | Owner | Properties |
|---|---|---|
| `.gate__intro` | CSS keyframe | opacity, transform (entrance) |
| `.env` | CSS transition | transform (hover lift / press) |
| `.env__seal` | CSS transition + `translate` | transform (hover/press) |
| `.env__seal-art`, `.env__flap`, `.env__letter`, `.env__stage`, `.gate` | WAAPI via `motion/mini` | transform, opacity, z-index |
| Hero parts, `Reveal`, nav, `DrawPath` | Motion React | opacity, transform, pathLength |
| `.nav__link::after`, buttons | CSS transition | transform, colour |

Only `transform`, `opacity` (and a discrete `z-index` flip on the flap) are animated. No continuous/looping animation exists anywhere (no petals, no bobbing cues). No blur/filter animation.

## The envelope (`components/envelope/`)
Layers (back → front): shadow, back panel, **letter**, pocket (V-shaped front, SVG), **flap** (two faces: outside + lining, `backface-visibility: hidden`), **wax seal**. The stage has `perspective: 1400px`; the flap hinges at its top edge.

Timeline (seconds from press):

| t | Action |
|---|---|
| 0 → 0.55 | Seal presses (scale .9) then lifts away (scale 1.12, fades) |
| 0.3 → 1.25 | Flap swings `rotateX(0→180°)`; at its edge-on point (0.77) z-index drops under the letter |
| 1.0 → 2.85 | Letter rises (`translateY -56%`, ease-out) then swells (`scale 1.18`, ease-in-out) — one animation, two eased segments |
| 1.9 → 2.4 | Letter fades; stage settles back 1.8 → 2.65 (`y 18px, scale .97`) |
| 1.9 | `onReveal` — hero entrance starts underneath |
| 1.9 → 2.7 | Overlay fades out; `onOpened` fires on completion: `inert` removed, focus moves to the hero heading |

Press feedback: hover lifts the envelope 4 px and the seal 7 % (pointer devices only); pressed scales the seal to 93 %.

Constants live in `T` at the top of `EnvelopeGate.tsx`; change timings there.

### Accessibility behaviour
- The gate is `role="dialog" aria-modal`; the dialog itself takes focus on load (announced, no focus ring), first `Tab` lands on the envelope button.
- `Enter`/`Space`/click/tap all open it; a second press while opening is ignored (`aria-disabled`, not `disabled`, so focus isn't dropped).
- **Skip**: the visible "Skip to invitation" button and `Escape` complete the sequence immediately. The invitation is in the DOM underneath from the start (inert while closed), so nothing is generated by the gate.
- Reduced motion: still one press, but the sequence collapses to a 0.2 s fade.
- The Skip button stays visible and clickable while the sequence plays (touch users have no Escape key).
- Failure: a render error is caught by `GateBoundary`; an error starting the animations (including the reduced-motion fade) is caught in `open()`. Both drop the gate and show the page (tested by stubbing `Element.prototype.animate` to throw).

## Hero entrance (`Hero.tsx`)
Variants with `staggerChildren .13`: greeting rises → each name slides up inside an `overflow:hidden` mask (1.15 s, ease-out) → ampersand → rule scales in → date → long date → place → scroll cue (1.6 s delay). Two botanical sprigs draw their stem and leaves with `pathLength`. No per-character animation, no overshoot. `play` flips when the envelope dissolves (or immediately if the envelope is disabled).

## Scroll reveals (`Reveal.tsx`)
`whileInView`, `once: true`, `amount: .2`, bottom margin −8 %, 24 px rise, 0.9 s ease-out. Siblings pass `delay={i * 0.06–0.1}` (capped at 3 steps so nothing waits). Plays once: scrolling away and back never re-hides content (tested). `opacity/transform` only, so there is no layout shift.
Timeline line (schedule) draws with `scaleY` when it enters view.
Caveat: elements below the fold stay at opacity 0 until scrolled to. Full-page screenshot tools that don't scroll will show blank sections — scroll through first (the e2e tests do).

## Countdown
One `useNow` ticker aligned to second boundaries, paused while the tab is hidden, cleaned up on unmount. Only the numeral whose text changed re-renders (`memo`). Digits are not animated. Screen readers get a minute-resolution `aria-label` on the `role="timer"` element (not announced per second). Phases: `before` → grid; `during` → "Today is the day"; `after` → thank-you (calendar buttons hidden).

## Navigation
Plain hash links. The nav appears once the hero leaves the viewport (IntersectionObserver), slides in (0.45 s), highlights the current section via a second observer (`aria-current="location"`). Mobile: menu sheet with `AnimatePresence`, closes on link/`Escape`/resize, focus returns to the toggle, page scroll locked while open. Back-to-top is `href="#top"`. `html { scroll-padding-top }` offsets the sticky bar.

## Static mode and capture mode
`useStaticMotion()` (`components/animations/useStaticMotion.ts`) is the single switch every animated component uses. It is true when any of these holds, and then everything renders in its final state with no movement:
1. the visitor prefers reduced motion;
2. capture mode is on (`?capture`, below);
3. the browser can't run the animations (no `IntersectionObserver`, no `Element.animate`, or a probe animation throws).
Case 3 is the guarantee that a failing animation engine never leaves content at `opacity: 0`.

### Deterministic screenshots — capturing the complete page
Sections normally fade in as they enter the viewport, so a plain full-page screenshot of the live page shows blanks. Use capture mode:

```
http://localhost:4173/?capture&now=2027-01-01T00:00:00Z
```
- `?capture` — no envelope; every reveal, hero entrance, line-drawing and timeline renders in its final state; images load eagerly; CSS animation/transition is disabled (`html[data-capture]`).
- `&now=<ISO instant>` — optional; freezes the countdown clock so the numbers are identical on every run. Ignored without `?capture`.
- Wait for the readiness signal instead of sleeping: `await page.waitForSelector('html[data-capture-ready="true"]')`. It is set after `document.fonts.ready`, all images decoded, and two animation frames.
- Then `await page.screenshot({ fullPage: true })`. `e2e/quality.spec.ts` does exactly this at 390×844 and 1440×1000, with and without `prefers-reduced-motion`, and asserts two consecutive captures are byte-identical.
Normal visitors never get this mode (it needs the query string and changes nothing else); an e2e test asserts normal behaviour is unchanged without it.

## Reduced motion
`<MotionConfig reducedMotion="user">` + explicit checks: `Reveal`/`DrawPath`/timeline render static elements; hero uses `initial={false}`; nav appears without sliding; the envelope fades; CSS transitions shrink to 10 ms and `scroll-behavior` is `auto`. Content is visible immediately.

## Adding an animation
1. Pick the property owner from the table above; do not give one element two owners.
2. Use `Reveal` for entrances; use the tokens in `animations/tokens.ts`.
3. Guard anything that moves with `useReducedMotion()` (or put it in a `@media (prefers-reduced-motion: no-preference)` block).
4. Never make information depend on the animation having run.
